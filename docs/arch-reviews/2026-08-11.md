裁决仍为 **CRITICAL**：9 项高风险、18 项中风险。本轮最紧急的新证据是生产内部鉴权配置丢失：`cecelia-node-brain` 运行 `1.272.14@4085ca68c1`，但容器没有 `CECELIA_INTERNAL_TOKEN`；宿主经 `localhost:5221` 访问在 Docker 网桥下又不被识别为 loopback，`POST /api/brain/issues` 实测返回 503 `INTERNAL_AUTH_NOT_CONFIGURED`。同一 SHA 的 Gate3 run `31510315901` 因 `deploy-local.sh exited code=1` 失败，Brain 的 deploy status 随后已回到 `idle`，无法保留失败终态。PR #4814 已准确覆盖 sidecar 未挂载 token SSOT 的根因，但当前仍 OPEN/DIRTY；在它合入并以匿名 401、带凭据 2xx 验收前，宿主 `/dev` 与巡检写入口不完整。

当前任务再次实证 review 身份与时间合同分裂：文件 lock 持有 run id `1d8d7640-...` 且 Codex 进程存活，但 tasks.payload `current_run_id`、`run_status` 与 `driver_heartbeat_at` 全为空；标题是 16:00 UTC，`created_at/started_at` 却被 API 读成 03:00/03:07 UTC，`claimed_at` 才是 16:07 UTC。`triggerCodexReview()` 仍没有调用已有 `updateTaskRunInfo()`，只解析 PASS/FAIL，callback 也不验证 `response.ok` 或 CAS `applied`。recovery 的 in-progress 投影继续漏取 `executor_kind`，tick 仍在 60 秒后只释放共享锁而不取消旧执行。

两项风险得到实质改善。第一，PR #4779 已合入，main、production 与 staging 的 migration floor 当前都为 410；408–410 的生产先落库事故已从“正本缺失”收敛为“防复发门禁缺失”。第二，PR #4801 已让 `/api/brain/map/manifests` 成为写权威、`/api/brain/map` 成为统一读接口，生产路由全部消费 `src/lib/*`；旧 `src/map/manifest-*`/projector/state-resolver 只剩未引用实现与测试，双写高风险已解除但清理债仍在。

另有一个新中风险：生产与 staging 日志均显示 `incident-reporter` 的 `ON CONFLICT` 因 `recurrence_count` 列歧义而失败，代码仍写 `recurrence_count = recurrence_count + 1`，单测只匹配这段字符串并没有真实 PostgreSQL 行为验证。由于生产内部写入口当前 503，本轮遵循 API-only 约束，未直接写数据库；该缺口必须在鉴权恢复后登记并以真实 PG 回归收口。
