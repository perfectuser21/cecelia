## 4B Structural Health Findings

- 环境隔离目前是多个局部开关的并集，而不是实例级不变量。`BRAIN_PREVIEW` 关闭两个 loops，`CECELIA_TICK_ENABLED=false` 不覆盖克隆 DB 的 enabled=true，`CECELIA_TICK_HARD_OFF` 又只控制主 Tick；任何单项绿色都不能证明零副作用。
- review 以 task UUID 命名共享文件锁，却不使用原子独占创建，也不把 environment/run-id 写进 DB。两个 Preview 对同一 UUID 的第二次写入覆盖第一 run-id，说明锁既不是互斥量，也不是权威身份。
- migration 权威不受合并状态约束。已关闭 PR 的 413/414 可以进入 production，开放 PR 又可复用 413；ledger 只按版本号去重，把“同号不同迁移”静默压成已应用。
- #4860 的 Session Controller 设计依赖新列，但其 Preview 已实证没有这些列。单测/PR 状态无法替代在目标 DB 上验证 migration 描述、hash 与物理对象。
- staging 主 Tick health 已能报告 stopped，却仍运行并写入独立 scheduler/promotion 副作用；health 仍只描述部分系统生命周期。
- 三条 nightly 全红、Real-Machine 全绿、Gate 3/Auto Staging 绿色、scheduled Release Gate 红色，质量、部署和发布没有共同的完成语义。
- 本轮 main 增加大量 Kernel 合同测试与 smoke，但核心文件规模仍上升，跨模块入口、迁移和运行身份的不变量没有被同一 E2E 覆盖。
