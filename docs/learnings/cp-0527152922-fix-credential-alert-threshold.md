## 凭据告警改为失效检测（2026-05-27）

### 根本原因

`ALERT_THRESHOLD_MS = 8h` 与 Claude OAuth token 生命周期（8h）相等，导致 token 每次刷新后 1 分钟就进入 `expiring_soon` 状态，Brain tick 每 30 分钟持续误报告警。

更深层的设计错误：告警逻辑基于「剩余时间」，而不是「自动修复机制是否失效」。只要 cron 在正常工作，任何基于时间的告警都是噪音。Codex 5 个账号已静默失败 2 周、真正失效的告警反而没人收到，根因相同。

### 下次预防

- [ ] 凡涉及「自动维护机制」的告警，触发条件必须是「机制本身失效」，而不是「某指标接近阈值」
- [ ] 新增告警前先问：「如果这个告警触发，用户能做什么？做不了 → 删掉告警」
- [ ] cron/自动刷新类场景：告警条件 = 已过期超过 `max_retry_interval`（本例 1h = cron 周期 2h 的一半）
- [ ] 静默失败比误报更危险：Codex refresh 失败 2 周无告警，下次类似机制上线时必须加失败路径告警
