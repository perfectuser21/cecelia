## Coding workflow 终态镜像与确认语义（2026-10-15）

### 根本原因

只枚举 open PR 的镜像器看不到合并、关闭与后续停止预览；合并时删远端分支又破坏 task_id 读取。终态回执 GET 失败后用空 prior 写入会丢历史，PATCH 失败后本地 merged 阻止后续补账。

外部合并与本机标记之间存在崩溃窗口。持久化动作前的精确批准 head，再核实 GitHub 实际 MERGED，才能恢复收账而不重复合并。回执待办须先于本机 merged 标记持久化。

Learning API 没有幂等保证，HTTP 200 也可能只写入部分。发送痕迹先落盘，返回的数量、唯一 IDs 与分页读回原文全部匹配才确认；未知结果保留待办，不盲重发。已有终态回执但 Learning 未确认时，明确标为未确认。

本地固定 Git 组合来源预检发现，测试夹具经环境变量注入 CLI 时不会自动形成静态 import 边；旧夹具顶层执行还会在导入时读状态、写日志并退出宿主。把夹具做成可安全导入的 CLI 模块，并让沙箱真实消费其导出的自身路径，可保留执行语义与真实依赖关系，无需扩大来源守卫。

### 下次预防

- [x] 终态待办独立于 open 列表和日志保留期；超出最近列表窗口后按有界轮转核实实际 PR 状态。
- [x] 回写前核对 task、repo、PR 身份与成功 GET；仅替换自身镜像字段，保留扩展历史并移除已撤销字段。
- [x] 外部成功后的每个落盘边界都加入中断恢复测试；重启只补账，不扩大合并权限。
- [x] 非幂等写入分开记录发送、回执、读回确认；部分或未知结果不自动重发。
- [x] 新交接使用 AI QA 与最终批准轮次，历史轮次保留原 FAIL/PASS；不把历史记录数写成全通过。

- [x] CLI 测试夹具导出真实路径供调用者使用；以真实子进程检查 import 无副作用、直接执行退出码与相对路径/软链入口，不加装饰性 import。
