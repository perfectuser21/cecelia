## Codex QA 原生证据完整传递（2026-10-17）

### 根本原因

QA 的语义判断与命令事实来自同一份模型手抄报告，遗漏失败或重复命令、截短输出和裁判输入后仍可能进入后续流程。把“接受验不了的限制”转换成 PASS 混淆了处置与实际验证；独立扫描 Markdown 字段也会把输出中的文本当作报告结构。新报告装配必须同时保留原有截图和隔离门禁。

### 下次预防

- [x] 控制器保全当次原生事件与模型草稿，权威条目和完整有序命令账绑定同一任务、轮次、HEAD、控制器及隔离回执；原始语义 FAIL/CANNOT_VERIFY 不由事实装配改成 PASS。
- [x] 裁判全量材料先冻结，再按实际 UTF8 stdin 独立计算哈希和字节数；最终总预算、输送错误、内容偏差及来源绑定失败均阻断。本地管道完成不声称模型消费 ACK。
- [x] 验不了的旧处置必须匹配原问题、规格、环境、控制器与限定下一轮；匹配仍保持 CANNOT_VERIFY。原生输出中的围栏、标题及字段保持数据身份，截图路径原字节和缺图校验不得因格式装配丢失。
- [x] 真实零字节、仅换行、空白、缺字段、未知退出码及未完成命令分别验收；新增来源协议不能通过删除标记降级成旧协议，旧可信原件按原合同验证。

本条记录修复机制及本地回归所验证的边界；正式来源准入、精确提交 CI、自然运行时加载和两条全新任务 C01–C12 的结果分别登记，不以本地夹具替代产品验收，也不改写旧失败样本。
