## 手机巡查来源准入与 F3 测试消费修复（2026-10-10）

### 根本原因

手机巡查属于系统看护，原获客试点入口无法声明它的真实来源。首次来源不存在于旧 Git 树，必须以固定 base/introduced 的完整 Git 事实及正式 Workflow/Activity 身份登记，不能伪造空候选或借用获客能力。

既有 F3 消费者证明了测试配置，却没有将实际 include/exclude 选择的毕业池和必需版本脚本写入来源绑定。新增 schema 必须按固定 Git 的版本标记启用，避免重算旧冻结快照。旧跨仓 CI 调用者还需要证明巡查专用预读在其 scope 中恒不执行；匹配文件名不能替代条件、环境和字节证明。

### 下次预防

- [ ] 新能力先核真实归属及固定 Git 入口，再登记窄 scope；源码准入与生产运行证据分开保存。
- [ ] 改来源解析协议时，同时验证旧定义完全兼容、新定义持久化读回及动态配置拒绝。
- [ ] 增加 CI 条件分支时，保留必需 runner，并验证错误条件、环境覆盖和脚本字节变化仍被拒绝。
- [ ] 开 PR 前用已发布工具、正式快照和实际 Git diff 联合验收；候选工具通过不能代替可信旧工具的准入证明。
