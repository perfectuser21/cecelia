## 工厂执行单改走 Commander+外壳：派发路径切换要先装开关（2026-10-12）

### 根本原因
- 推进器每 5 分钟按配置建单，Brain 侧一合并部署就会按新路径建 workflow_dispatch；而 Commander 侧启动器（zenithjoy deploy.sh 部署）还没上，Commander 只会 exit 4 → 单 failed、裁判计 fail，白白污染台账滑窗。
- 两个仓库跨机部署无法原子切换，路径切换点必须是一个可单独翻的运行时开关（brain_config），而不是"配置写了就生效"。
- 旧派发器（factory-dispatcher）与新路径对锁的纪律相反（派发器代领+执行会话放 vs 外壳代领+执行会话不碰），正文纪律不能共用一行，只能按路径替换。

### 下次预防
- [ ] 改"谁来领单/谁来派"的路径时，先问：两端是否同时上线？不是就加默认关的运行时开关，等下游部署验收后再翻
- [ ] 新路径失败如果不产出 result.delivery，推进器的在途判定会认为"无在途"立刻再建单——失败也要留一份标明来源的交付
- [ ] 执行者交付的裁判证据必须来自系统代码（外壳 runner 落盘），LLM 汇报（COMMANDER_RESULT）只作陪跑说明
