## b44 — harness pipeline A→B→C phase=done 集成测试（2026-05-17）

### 根本原因

B43 集成测试只验证了 `final_e2e_verdict='PASS'` 和 B→C 节点调用次数，但没有断言 `reportNode` 真正写入了 `initiative_runs.phase='done'`。如果 `reportNode` 的 DB 写入被 idempotency gate short-circuit（`state.report_path` 已有值），测试仍然 GREEN，但 phase 没写进 DB，pipeline 实际上处于不完整状态。

### 下次预防

- [ ] 任何测试 reportNode 的场景，必须先断言 `final.report_path` 非空（确认 reportNode 没被 idempotency gate 跳过），再断言 DB 写入
- [ ] `pool.query` 断言 filter 应同时包含：表名（`initiative_runs`）+ 字段（`phase`）+ 值（`done`），精确到 1 次（`toBe(1)`）而非 `toBeGreaterThan(0)`
- [ ] TDD "RED" 阶段：对 integration test of existing code，`await undefined` 不 throw，不能靠省略 mock fallback 来制造 RED。改为先写带故意错误断言的 test（如 `params.includes('NEVER')`) 来确保 RED 状态
- [ ] smoke.sh 的 grep pattern 应与实际断言代码保持精确对应，避免重构后 smoke 通过但断言已弱化
