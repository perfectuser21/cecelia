# 手机忙排队等待误用执行超时当等待上限（09-30）

### 根本原因
- #5698 给「手机忙回队」设等待预算时图省事借用了 min(任务执行超时, 120 分钟)。主理人指出：任务在 Brain 排队时还没开始执行，执行超时只该从真正开始执行算起——30 分钟超时的任务排队 31 分钟就被判失败，活没干就销账。
- 查截止字段时发现入账把「预期开始时间」（英文 Plan Date 起点 / 旧列预期完成日期）回落写进了 due_at：生产在队 3 张秋米任务 due_at 全等于开始时间。若直接拿 due_at 当截止，任务一忙就判过期。
- tasks.due_at 是 timestamp without time zone，入账写上海墙钟，生产 PG 会话 UTC；裸读靠 node 进程时区猜，换环境差 8 小时。

### 下次预防
- [ ] 「等待」和「执行」是两段时间，各自有上限；借用对方的预算前先问语义是否相同
- [ ] 读一个字段当判据前，先去生产看它实际存了什么（本次 due_at == scheduled_start）
- [ ] timestamp without time zone 列的读写都显式写时区，不依赖会话/进程时区
