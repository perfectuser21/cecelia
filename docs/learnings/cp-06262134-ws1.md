# Learning — Dashboard 首页 Harness 工厂线贯通状态标识 (ws1)

## 背景
用一个最小、可见、可验证的 dashboard 改动，端到端验证 harness 工厂线（staging:5223 → promote → live:5211）真从代码走到生产。

## 关键决策
- **无条件渲染**：固定标识组件挂在 `App()` 的 `ThemeProvider` 内、`InstanceProvider`/`AuthProvider` 外。
  原因：final-e2e（mac_web）用 `vite preview` 起静态 build、`storageState: undefined`（未登录态）访问首页，
  且无后端。若把标识放在 `AppContent` 的认证/实例加载守卫之内，未登录或 config 拉取失败时会被早退的 loading
  屏挡住，E2E `getByTestId('harness-pipeline-status')` 必然 timeout。挂在守卫外保证任何状态都首屏可见。
- **静态文字 + 显式配色**：emerald-600 底 + 白字，不依赖 `dark:` 变体，暗/亮主题（`emulateMedia` 切换）均清晰可见。
- **逐字固定**："Cecelia Harness 工厂线已贯通"，不做同义改写（合同硬条款）。

## 范围
只动 `apps/dashboard/`：新增 `HarnessPipelineStatus.tsx` + `App.tsx` 挂载。不改流水线脚本、不新增 API/DB。

## ⚠️ 关键发现：SEAM 合并前/合并后编排死锁（fix_mode 复盘）

本 walking-skeleton 暴露出 harness 编排层一个**结构性死锁**，generator 无法在本 PR 合同范围内修复：

**事实链（容器内实测）：**
- 实现完整、40 项 CI 全绿、本机 build 产物 dist/assets 真含固定文字（逻辑断言全过）。
- `live:5211` 可达（HTTP 200），但其 JS bundle **不含**新固定文字（仍是旧 bundle）。
- 新文字进入 live bundle 的唯一路径：`merge → staging 部署 → staging E2E → promote → live`（见 PRD 流水线序）。
- `merge` 由 `mergePrNode` 在 **evaluator PASS 之后**执行（SKILL v7.5 红线，禁止 generator 自 merge）。

**死锁：** evaluator 的 SEAM 断言「live:5211 bundle 真含固定文字」在合并前必然 FAIL（live 可达但 stale）
→ evaluator 永不 PASS → 永不 merge → 永不 promote → live 永远 stale → fix loop 空转。

**「环境探测式」探测的盲区：** ac4f9c3a7 把 SEAM 命令改成「不可达(000)→SKIP exit 0」，
但 live:5211 是**可达(200)但 stale**，不触发 SKIP 分支，仍走到 hard-fail「promote 未生效」。
探测只覆盖了「端口不可达」，没覆盖「可达但内容是合并前旧版」这一合并前必然态。

**为何不能在本 PR 修：**
- 单条 bash 命令无法区分「合并前 live=旧 bundle（合法 pending）」与「promote 真失败（应 FAIL）」——两者都表现为 stale。
- 把 SEAM 改成 stale→exit 0 会削弱真目标 oracle（promote 真坏也放过），违反 CONTRACT IS LAW。
- 正解是**编排层**：SEAM/E2E-seam 应在 merge 后由流水线跑（真 promote 已生效时），而非作为 evaluator 合并前 gate。
  这属于「不改流水线脚本」合同范围之外，须独立 /dev 任务修 evaluator 编排。
  → 已建 Notion/Brain issue `fb02217c-d658-4712-83dc-663bc8d59a1d`（P1，sub-area=engine）跟踪。

**generator 结论：** 实现侧无 bug 可修（实现正确 + CI 全绿 + 逻辑断言全过）。
