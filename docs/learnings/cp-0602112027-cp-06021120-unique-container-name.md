## 容器名唯一化 — 根治同 task 多轮撞名(125)/误杀(137)（2026-06-02）

### 根本原因

容器名只按 taskId 算（cecelia-task-{id12}）。**不同任务不撞，但同一条 harness pipeline
内部多轮 GAN 容器（proposer/reviewer 各轮）共享同一 taskId → 全同名 → 自己撞自己**
（exit 125）。我先用 docker rm 清理（#3230），rm -f 又误杀活容器（137，#3234 改 rm）。
绕了一大圈，正解是用户一句话点破的：**容器名带轮次/随机后缀，每个唯一就不撞**。

### 下次预防

- [ ] 资源命名要按"实际并发实例"唯一，不能按逻辑实体（taskId）——一个 task 会起 N 个容器
- [ ] 改命名方案前先查所有"按名查找"的消费方（grep 重算逻辑），精确匹配改前缀匹配
- [ ] 容器名前缀（cecelia-task-{id}）保留作 quarantine/recovery 的查找契约，只在末尾加唯一后缀
- [ ] 遇到"自己撞自己"先想"是不是同一标识被复用"，别急着加清理/强杀的 workaround
