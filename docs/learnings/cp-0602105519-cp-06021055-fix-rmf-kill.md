## #3230 的 docker rm -f 杀活容器（exit 137 假 OOM）（2026-06-02）

### 根本原因

#3230 为修 exit 125 撞名，加了 spawn 前 `docker rm -f {name}`。但 `-f` 会强杀**正在运行**的容器 → exit 137。我一度误判 137 是内存 OOM（要加内存到 4GB），实际 docker events 显示 `[kill]` 无 `[oom]`，且实测 proposer 峰值仅 332MB（2GB 上限 6× 余量）。before/after 铁证：#3230 前 137=0，之后 137=11~15。

用一个偶发、可被 LangGraph 重试自愈的 125，换来了"杀活容器"的更糟回归。

### 下次预防

- [ ] `docker rm -f` 会强杀运行中容器；清残留只该用 `docker rm`（不带 -f），活容器会安全报错跳过
- [ ] exit 137 ≠ 一定 OOM：先用 `docker events`（有无 `[oom]`）和 cgroup 实测峰值定性，别看到 137 就加内存
- [ ] 修一个偶发自愈问题前，先评估修复本身的副作用是否比原问题更糟
