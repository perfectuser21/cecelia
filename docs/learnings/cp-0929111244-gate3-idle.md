# Gate3 等待步把 idle 当成功，漏部署无人察觉

## 现象
2026-09-28/29 两次（#5635、#5654 合并后）Gate3 显示成功，但生产 `deploy/status.git_sha` 仍是上一个提交，只能人工 `gh run rerun` 补部署。

### 根本原因
- 「等待 Deploy 完成」只看 `status` 字段：`idle` 且等了 30 秒就输出「可能无变更，视为成功」退出 0。
- 合并触发 webhook 时上一次部署仍在跑，本次请求实际没有执行（或被 409 直接跳过），轮询看到的 running/idle 都是前一次部署的，与本次提交无关。
- 后续效果断言只比版本号和 uptime。非版本号 bump 的提交版本不变，前一次部署刚重启过的 uptime 也「新鲜」，于是断言同样放行。
- 本质：判定「部署成功」时没有把部署对象（git_sha）和本次提交对上。

### 修法
- 判定逻辑抽到 `scripts/ci/gate3-wait-deploy.sh`：终态时部署 sha 等于本次或为其后代（`git merge-base --is-ancestor`，本地缺提交时退回 GitHub compare API）才成功。
- running 且 sha 旧只等待；终态不含本次则重触发 webhook，最多 2 次，耗尽 exit 1。
- 触发命令抽到 `scripts/ci/gate3-trigger-deploy.sh`，首次触发与重触发共用；409 不再跳过等待步。

### 下次预防
- [ ] 任何「部署成功」判定必须比对部署对象标识（sha），不能只看状态字段或版本号
- [ ] 「无变化视为成功」类乐观出口必须带可验证的前置条件，否则一律视为失败
- [ ] CI 判定逻辑写成可本地跑的脚本 + 假数据测试，yaml 只做接线
