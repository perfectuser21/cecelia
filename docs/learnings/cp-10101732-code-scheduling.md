## 正式纯代码巡查的独立容量（2026-10-10）

### 根本原因

中央 dispatcher 和优雅降级将脚本与 AI 任务放在同一预算中。手机巡查即使不调用 LLM，仍因 AI 池已满而等待或被暂停；同项目人工开发的互斥也挡住了独立设备任务。手动派发成功只能证明执行器可用，不能证明定时调度已接通。

新入口复用中央 tick，每轮最多尝试一条明确 JSON 布尔 `runtime_requires_llm=false`、关联真实 active Workflow 且不要求 Cortex 的 script_run。AI 池不计这类任务；目标主机新鲜健康、实际压力、脚本并发、熔断、设备原生锁、硬依赖和停止开关继续约束执行。

真实 CI 还发现两项测试合同需要同步：新 lib 模块须放置邻接测试；AI 预算为零的 tick 集成测试应严格断言仅一次 `dispatchNextTask(null, {codeOnly:true})`。在 scratch 独占 schema 复现该断言失败后，修正为六项通过，保留所有主机副作用边界断言并清理独占 schema。

源影响门禁要求每条辅助路径声明实际 owner。版本提示测试属于现有版本 gate，须由正式 F3 消费源选择器认领；不得为通过门禁把它虚挂到 dispatcher。生产发布与自动验收尚须分别取得事实证据。
