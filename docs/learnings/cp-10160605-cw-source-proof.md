## 编码流水线报告来源必须由控制器当场留证（2026-10-16）

### 根本原因

A3 的第二轮 QA 无法同时满足来源证明和开发报告隔离：Git 作者、manifest 归属、文件哈希都不能证明是谁执行了登记。把这些元数据交给模型解释，既不能补足来源，又会诱使 QA 读取禁止读取的开发自述。

独立回归还复现了三条绕过：登记后再提交别的改动会把末尾提交误认成登记提交；Git replace/grafts 能改变固定 SHA 的解释；Commander 获准写整个日志目录时能触及 QA 状态。

### 下次预防

- [x] cwstagecapture 控制器从实际子进程 stdout 管道封存原生执行与阶段结果；可变 transcript 文件和任务输入不能选择证据根或提供通过证明。
- [x] cwrecordproof 登记事务绑定调用前 HEAD、真实 registrar 返回、直接子提交、文件模式与字节；禁止事后补签。固定 Git 读取禁用 replace，拒绝 grafts。
- [x] cwsourceisolation Codex 各沙箱拒绝读取或改写控制器证据目录及 Git 安全元数据；保留正常工作区修改和 git commit。Commander 仅能写本次裁决目录。
- [x] cwsourcegate 合并前核对受保护的同轮 QA 与独立裁判 PASS，裁判绑定 QA 事件及被测 HEAD；状态文件中的 PASS 不足以放行。

### 证据边界

来源证明仅说明控制器当时收到了什么以及登记了哪个提交，不代替产品验收中的真实命令、输出、截图和行为判断。单测中的原生事件是明确的 fixture；真实 Codex sandbox 子进程验证只证明文件权限，不能宣称两条无人任务已经跑通。完整流水线仍需修复合入后的两个新任务验收。
