## dep-audit 被新公布 CVE 卡住所有 PR（2026-06-01）

### 根本原因

`npm audit` 查的是实时 advisory 库，新 CVE 随时公布会让**同一份未改动的 lockfile** 从 pass 翻 fail。今天 qs + uuid + vitest-UI 三个 advisory 新公布，导致所有 PR 的 dep-audit 步骤突然失败——与提交内容无关。原 CI 用裸 `npm audit --audit-level=critical`，无任何豁免机制，一旦命中无修复版的 advisory 就死锁全部合并。

### 下次预防

- [ ] dep-audit 必须支持文档化白名单：对"无 non-breaking 修复 + 本项目用法下不可利用"的 advisory 可豁免，但每条须注明不可利用原因+不能修原因+移除条件
- [ ] 白名单纪律：严禁把"可修"的 advisory 加进来图省事；可修的（如 qs）必须 npm audit fix
- [ ] CI 出现"代码没动却突然挂"时，先怀疑外部实时数据源（advisory 库 / 时间敏感检查），不是本 PR 引入
