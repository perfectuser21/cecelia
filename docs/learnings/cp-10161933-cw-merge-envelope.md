## 可信读取链变更先交付严格来源兼容（2026-10-16）

### 根本原因
来源收集器使用完整已审语法封套。受保护存储新增 merge 事件，且 evaluate 改为通过严格读取器消费合并链后，旧收集器应当拒绝未知组合。只加存储 kind 或只登记 import 都不足以证明整条读取关系。

### 下次预防
- 冻结完整候选后，先通过独立 PR 交付有限兼容，再交付运行器行为。
- 旧完整组合保持；新 store、evaluate 和两个读取器必须精确配套，未知混搭失败关闭。
- 区分真实读取、静态调用约束和实际业务执行；控制器身份对文件的字节读取不等于执行写入器。
- 仅在 evaluate 实际被选择时登记其读取关系，不给 build、publish 或未选择阶段扩大来源认领。
- 保留缺模块、替身、跳过读取、输入自述和退休 Claude 执行等反例；真正验收入口另做子进程验证。
