## 发现的问题

### [DESIGN] 设计缺陷

- **LLM evaluator 前缺少确定性预检**：作弊型 contract（伪闭合围栏、tautology、env_missing 绕过）会照常 spawn LLM evaluator，浪费 ~$5-7/容器且可能被绕过。
  - 修复：新增 `contract-gate.js` 作为单一来源确定性 gate（数据化 RULES 规则表 + ENV_CAPABILITY 环境能力清单，零 LLM）。`evaluateContractNode` 在 spawn LLM evaluator 前接同一 gate，命中 ok=false → verdict=FAIL 不 spawn；异常 fail-open。

### [BUG] 代码缺陷

- **artifact-gate fetch fail-open**：`verifyContractArtifactsForPr` 的 git fetch 未用显式 refspec，远端分支取不到时静默 fail-open。
  - 修复：改用显式 refspec `<branch>:refs/remotes/origin/<branch>`。

### [INFRA] 基础设施问题

- **harness-report 运行环境无 Brain**：本次 report 在一个无 Brain(localhost:5221)/无 Postgres/无 docker 的环境被 spawn，导致 Phase A 全部 API 写回步骤与 Phase B 状态同步无法执行。
  - 现象：`localhost:5221` 与 `localhost:5432` 均拒连，docker daemon 不可用，env 无 DB 配置。
  - 影响：Brain 任务状态、Dashboard、Notion Notes/Registry、飞书通知、Phase B db-update 全部阻断。
  - 缓解：只完成不依赖 Brain 的本地文件产出（harness-report.md / learning.md / index.html）；API/同步待 Brain 在线后手动补同步本 skill。
  - **建议建 Issue**：report 节点 spawn 前应校验 Brain 健康，否则形成"假完成"（报告写了但状态/同步没回写）。
