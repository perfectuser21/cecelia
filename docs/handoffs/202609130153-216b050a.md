4. **【已立 issue `d6174890-5697-40cf-a96d-2b36207c03f4`（P1/brain）】watchdog 必然误杀有头接管的 harness_initiative 任务**
   > **勘误（09-13 核实）**：本条初稿归因为「本任务 `task_type=dev`，判据没区分 task_type」——**该归因是错的**，两处都别再照抄。
   > 实测本任务 `task_type` 就是 `harness_initiative`；`harness-watchdog.js:313` 与 `:357` 两处查询**都**带了
   > `task_type = 'harness_initiative'` 过滤，判据并不缺 task_type 维度。

   真根因是**有头豁免用的是固定时间窗，而不是「是否有头接管」这个事实**：

   - `harness_initiative` 被人工 /dev 有头接管时**永远不写 `initiative_runs` 行**（人工流程不跑 harness graph），
     所以 `NOT EXISTS (initiative_runs ...)` 对有头任务**恒为真**。
   - 唯一保护是 `harness-watchdog.js:306` 的 `headedExemptPredicate`：
     `NOT (claimed_by LIKE '%interactive-dev-skill%' AND claimed_at >= NOW() - INTERVAL '40 minutes')`
     —— 只覆盖 claim 后 40 分钟（`HEADED_CLAIM_GRACE_MINUTES = 40`，`harness-watchdog.js:28`）。
   - 超窗后豁免失效，而判死阈值 `staleMinutesA = 20` 早已满足 → 置 `failed` 且**清空 `claimed_by`**。

   即：**任何有头 /dev 跑超 40 分钟的 `harness_initiative` 任务都会被误杀，是必然复发不是偶发**。
   本任务 08:09 认领、09:53 被判死，跨度 1h44m——而一次完整有头交付（PrepPRD→合同→TDD→CI 五轮闸）本就远超 40 分钟；
   代码第 27 行注释自己都写着「有头阶段正常就要 20-40min 才产生 run 活动」。

   放大伤害：`failed` 是死端（PATCH API 返回 `allowed:[]`，只能 psql 直设修回）；`claimed_by` 被清空后有头会话失去认领凭据，
   可能触发重复派发抢跑（见 memory `headed-dev-parallel-dispatch-incident`）。既有的 relay 容器存活探测
   （`harness-watchdog.js:329`）救不了有头场景——人工 /dev 不起 relay 容器，探测不到即 fail-open 保留判死。

   与 memory `zombie-reaper-false-kill-dev-tasks` 同族但**根因不同**，别当同一个 bug 修。

## 为什么原方案被推翻（三条亲验，供下一个大脑免于重犯）

| # | 原假设 | 实际 | 证据 |
|---|---|---|---|
| 1 | `production-transport.js:137` 守卫「已存在只是没触发」 | **死代码，生产不可达** | 判据是入参 `localMachineId` 且默认值即 `DEFAULT_LOCAL_MACHINE_ID`；`server.js:145` 只传 `{env,fetchFn}`、`attempt-cleanup-worker.js:208` 只传 `{env}`，四个调用方全不传 → `if` 恒为假 |
| 2 | 「身份叫 us-mac-m4 → 判本机执行 → 走 launchKernelProcess」 | **因果链不成立，改 env 不减一丝 CPU** | `harness-skill-relay.js` 对 `machineId`/`CECELIA_MACHINE_ID`/`machine` 匹配行数 = **0**；本机 spawn 唯一判据是 `payload.harness_runtime === 'kernel-v1'`，且绕过 `production-transport` 直接 `nodeSpawn` |
| 3 | 改身份安全 | **会掐断凭据签发** | `credential-broker.js:144` 与 `github-credential-broker.js:36` 硬编码 `controllerMachineId !== 'us-mac-m4'` 即 fail。这台 Brain 必须自称 `us-mac-m4` 因为它是**凭据权威** |

`CECELIA_MACHINE_ID` 真实语义 = **fleet 可调度节点身份 + 凭据签发权**，不是宿主物理机标识（`canonical-machine-id.js` 注释明示 hostname 被刻意忽略）。另有六处 allowlist 假设它恒等于 `us-mac-m4`，且历史上从未有人改过它。
