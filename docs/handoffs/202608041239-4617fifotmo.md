# Handoff：remote-bridge start 操作独立超时预算（PR #4617）

## 完成
- 根因确认：PR #1581（zenithjoy-workspace）Kernel Harness 攻击链验证（r18-r27）反复以
  `attempt_*_credential_fifo_write_failed` / 笼统的 `remote_bridge_start_timeout` 失败。
  逐步排除了权限（macOS ACL + virtiofs 手工复现证实 FIFO 读写机制本身正常且快，
  实测 <50ms）、entrypoint.sh 配置拷贝循环（8s，非瓶颈）等假设，最终定位到真正
  的结构性 bug：`remote-bridge-transport.js` 的 `start` 操作和 `inspect`/`cancel`/
  `terminal` 共用通用 60s 超时桶（`DEFAULT_REMOTE_BRIDGE_TIMEOUT_MS`），而 fleet-worker
  `attempt-runner.cjs` 内层 credential FIFO 写入超时也在同一量级——真实并发负载下
  内层写入耗时会逼近甚至撞上外层 60s，导致 Brain 侧先中止 HTTP 连接，report 出的
  错误码永远是笼统的 `remote_bridge_start_timeout`，掩盖了 fleet-worker 自己更具体
  的错误。无论把内层超时调多大（10s→25s→60s 全试过），只要 ≥ 外层预算就必然被
  外层先掐断——这是数学上的死结，不是"再等久一点"能解决的。
- 修复：新增 `DEFAULT_REMOTE_BRIDGE_START_TIMEOUT_MS=120_000`，`start` 操作单独走这个
  预算（可用 `KERNEL_FLEET_START_TIMEOUT_MS` 覆盖，语义对齐已有的 `KERNEL_FLEET_PREPARE_TIMEOUT_MS`）。
  `attempt-runner.cjs` 内层 FIFO 超时维持 `60_000`（新外层预算下留足 60s 网络/HTTP 开销余量）。
- TDD 全程：`remote-bridge-transport.test.js` 新增 2 个用例证明 bug 存在（start 之前共享
  generic timeoutMs）→ 实现修复变绿（97/97 pass）；`production-transport.test.js` 新增
  1 个用例验证新常量与 env 覆盖（15/15 pass）；`attempt-runner.test.cjs` 更新 fake-timer
  边界断言到 60s（104/104 pass）。
- 顺带修复：Brain 版本 bump 时漏掉了仓库根 `package-lock.json` 里 workspace
  `packages["packages/brain"].version` 这第三处版本记录（之前只知道 `packages/brain/
  package-lock.json` 内部两处），CI `gp-assertion-command-smoke.sh` 断言这个一致性，
  抓到即修（commit `0a6888321`），已在本 PR 一并修正。
- PR #4617 已合并（squash merge，CI 全绿：ci-passed / Harness V5 Gate Passed /
  Smoke Glob Runner Passed 三个必需 check 均 SUCCESS）。
