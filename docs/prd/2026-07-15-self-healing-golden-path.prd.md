## 1. 为什么是 golden path 而不是第八个散件

A1-A7 七发全部 MERGED，每发各带合同测试永久进 CI——单件不裸奔。但**串链层覆盖为零**：
每刀的测试 mock 掉相邻环节，"A5 改动是否剪断 A1 路径"今天无人能答。两天实战证明：
每修一个场景，真实世界立刻变出下一个场景（OOM→退出码误判→证据截断→绿灯死→宿主团灭）。
散件竞赛永远追不上现实；只有把整条链定义成 golden path 并每天演习，才能收口。

## 2. Golden Path 定义：一条任务从"中途死亡"到"零人工落账"

```
S1 死亡检测      容器/tmux 消失（watchdog 5min 轮询，现有）
S2 死因分类      【本刀新增】三源取证：容器退出码 + stdout 尾巴关键词 + tmux 屏幕内容
S3 对因处置      【本刀新增分类路由，处置器多数已存在】
                 exit 137        → 升内存档一次重点火（A7，已上线）
                 401/凭据类      → 换账号重点火；连续 2 次 → blocked + Bark（codex-login 手册代码化）
                 429/限流/quota  → 不烧 attempt，defer 到窗口重置再点火
                 tmux 卡交互提示 → kill session + 重点火（48h 两发实证：sqlite Press-Enter / 限流选模型对话框）
                 CI 红/BEHIND    → 重点火续跑（A1+A5，已上线）
                 CI 绿等 merge 死 → 【新增】补一根"只做 judge→merge→收账"的窄 prompt 收尾棒
                 未知            → 现行裸重试（attempt cap 不变）
S4 续跑原 PR     controller Step 0.4 外部真相重建（已上线，多次实证不开重复 PR）
S5 验收过闸      evaluator 原件 → judge 机械闸+AI 裁判（刀B + A6，已上线）
S6 外部真相收账  finalize 核 PR MERGED + evaluator gate（刀C + A2，已上线）
S0 宿主团灭恢复  【新增，横切】brain 重启后扫描全部 in_progress relay 任务批量走 S2（OrbStack 嗝一次团灭所有在飞 session 实证）
```

范围收敛：本刀新增的只有 S2 分类器、S3 的三条新路由（401/限流/绿灯死）、S0 批量恢复；
其余全部复用已上线件——**本刀的主体是把零件串成链并给链配验机，不是造新零件**。

## 3. 测试双层（决策 5b0690ca 铁律）

**L1 CI 串链集成测试**：一个测试文件走完 S1→S6 全链。规则：**不 mock 被改的边**——
分类器→处置器→spawn 参数→watchdog 判定相邻环节真调用，只 mock 最外层（docker/gh/DeepSeek 网络面）。
每种死因一条链路用例（7 条），断言从死亡事件到终态（重点火参数/blocked/defer/收账）全程状态迁移。

**L2 nightly 金丝雀故障注入演习**：每晚在 staging brain（5222）派一条金丝雀 harness 任务，
随机注入一种死法（OOM 128MB 容器 / kill -9 / 卡交互脚本），断言 N 分钟内系统自愈到位
（重点火带正确参数）或正确快速失败（oom_wall/blocked+告警）。演习结果写 incidents 档案（接刀5a）；
失败 → Bark Alex。这是整台自愈机器的每日验机流水线。

## 4. 成功标准

- 七种死因在 L1 串链测试各有一条全链用例，CI 常绿；任何人改动链上任一环节，剪断路径即红
- L2 金丝雀演习连续 7 天绿（含至少 3 种死法轮换）
- 死因分类日志可审计：每次收尸打一行 `cause=<分类> action=<处置> initiative=<id>`
- 复盘指标：下一轮 dogfooding 的零人工完成率相对基线 2/5 显著提升（目标 ≥4/5）

## 5. 铁律

- 测试禁 mock 真实外部命令行为（A4/A5/A6 三只虫的共同根因，EVA v3 口径）
- 不改 attempt cap 数值与全局并发闸；OOM 升档最多一级；分类器判不出 → 保守走现行路径
- 金丝雀任务打独立标记，禁污染真实任务统计与回归池
- 新增死因场景一律先补 L1 链路用例再写处置器（无闸不成文的链路版）

1. **A8-1 分类器+路由骨架**：S2 三源取证 + S3 路由表 + 已有处置器接线（OOM/CI红），L1 串链测试框架落地
2. **A8-2 三条新处置**：401 换号 / 限流 defer / 绿灯死收尾棒 + S0 批量恢复，补齐 7 条链路用例
3. **A8-3 金丝雀演习**：nightly 注入器 + incidents 落档 + Bark 告警 + 连续 7 天绿验收
