### R-1
针对: S-4, Q-4, I-4
严重度: 重要
场景: 控制器把 main 同步进本任务分支形成双父合并提交后，QA 按 Q-4 对该提交运行普通 `git diff-tree` 看不到路径，于是把合并提交中的 README 或报告改动漏出逐提交范围检查；若后续提交还原这些字节，最终 `git diff <base> HEAD` 也看不到这次越界改动。
依据: I-4 要求 QA 从固定 initial base 独立完整枚举提交 DAG、逐路径识别同步与本任务自产变更，并拒绝上游触本任务 README/报告及先改后还原；S-4/Q-4 只写“逐提交 `git diff-tree`”，而 Git 对合并提交的普通 `git diff-tree <merge-sha>` 默认不输出父边差异。独立 source gate 的通过事实不能代替 I-4 要求的 QA 自身逐提交范围检查。
说明: 将 Q-4 的每个提交核验步骤具体化：先取得提交及全部父 SHA，对双父同步提交分别比较父边的路径和内容（含 mode、删除），再与固定基线到 HEAD、暂存区、工作区和全仓未跟踪结果合并判定；加入一个同步提交触碰本任务路径、随后还原的可执行反例，要求 QA 报不能验收。
